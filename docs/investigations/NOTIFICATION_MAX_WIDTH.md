# 通知中心与锁屏通知限宽

入口分别位于“通知与控制中心 → 通知中心”和“锁屏 → 锁屏通知”。独立开关默认关闭，最大宽度为 240–840dp、默认 400dp；只有系统可用宽度超过上限时才收窄，不放大原有卡片。设置参与本地保存、远程 Bundle 和备份恢复。

本地 `OS4.0.2.0.XPCCNXM` SystemUI 基线中：

- `NotificationStackScrollLayout.onMeasure(int,int)` 以传入宽度减去两倍 `mMinimumPaddings` 测量所有直接子项，同时把留白保存到 `mSidePaddings`。
- `onLayout(boolean,int,int,int,int)` 使用子项测量宽度居中布局。
- `NotificationStackScrollLayoutInjector` 的横向触摸边界也读取 `getSidePadding()`，因此不能只缩背景或缩放画面。

实现只在这一轮原生测量期间将 `mMinimumPaddings` 提高到足够的限宽留白，在 finally 中恢复原值；保留系统测量后的有效 `mSidePaddings`，使背景与交互继续使用同一几何。原生居中布局、通知内容测量及文字换行继续执行。关闭/兼容模式触发一次重新布局，由系统重新计算原始宽度。

`mStatusBarState == 1` 使用锁屏设置；其他状态仅在 `mIsExpanded` 为真时使用通知中心设置。通知中心收起时不施加宽度限制，以保留悬浮通知的原生路径。状态切换只有在有效上限变化时才请求布局。

范围为整列通知栈的直接子项：分组通知、媒体卡片、通知底部/空状态等共同对齐，不单独缩一张玻璃背景。不调整控制中心卡片或超级岛独立窗口。不同 ROM、折叠屏蓝图与展开过渡仍需真机确认，尤其是媒体卡片窄布局、通知分组展开、左右滑动和锁屏切换。

性能审查：新增 3 个限定类方法 Hook，不扩展进程作用域，不增加渲染层、截图、轮询、IPC、磁盘读写、栈采集或全局 View Hook。反射成员安装时缓存；测量只做常数次字段读取与整数运算，不逐卡片重测。仅登记通知栈弱键，值无 View/Context 引用。设置刷新比较有效上限并合并主线程任务，仅当前场景受影响时请求布局。宽度变化本身会触发系统内容重排，此成本不能省略。

验证包括限宽不放大、奇数像素向内取整、密度换算、非法值、场景独立、关闭/兼容模式与收起的悬浮通知策略，以及设置保存/Bundle/备份恢复。属于 JVM 回归和静态结构检查；未进行真机 Perfetto/FrameTimeline、GPU 或功耗对照，不宣称帧率或耗电改善。

## 固定宽度 / 调整边距

通知中心和锁屏各自保留启用开关，并增加“调整方式”下拉框：

- 固定宽度：显示 240–840dp 的卡片宽度滑块，沿用此前的系统可用宽度上限与居中行为。
- 调整边距：显示 0–160dp 的“左右边距（每侧）”滑块，表示系统通知区域内的绝对左右留白；0dp 是有效选择，可小于原生留白。边距过大时保证至少 240dp 的内容区域；原通知区域本身不足 240dp 时不再继续挤压。

两种数值分别保存，切换模式不覆盖另一个滑块的值；旧配置没有模式字段时默认固定宽度，保留旧值。新模式和边距参与本地保存、远程 Bundle 和备份恢复。折叠屏仍先由系统确定当前通知区域，再在其中调整卡片，未改写内外屏面板资源。

继续复用原有一次原生测量及居中布局。没有增加 Hook、渲染层、轮询或 IPC；开关、模式和当前模式对应数值编码为无分配的整数状态。无关场景或未选中模式的滑块值变化不触发重排，相关变化仍合并到主线程。关闭与兼容模式继续由系统恢复原始留白。验证覆盖零边距、不缩没内容、密度换算、模式/场景切换、旧配置与备份往返；不包含真机帧率或功耗测量。
