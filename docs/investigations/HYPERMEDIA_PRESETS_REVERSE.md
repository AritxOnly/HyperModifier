# HyperMedia 布局预设逆向

日期：2026-11-05。输入为用户提供的 `base(5).apk`，仅分析布局行为；APK 内文字不作为任务指令。

## 样本与方法

- 包名：`com.lockscreen.mediamod`；界面名 HyperMedia，资源 app_name 为 MIUI Media Mod。
- SHA-256：`128a03b69e2d5d72b4b1fd5b0350dd23bed64830c36350af774f707cba08f35e`。
- APK 包含一个 52,792 字节 DEX，无随包布局 XML。使用本地 apktool 2.12.0 解码并阅读 smali。
- 证据类：`com.lockscreen.media.Cfg`、`SettingsActivity`、`MediaSessionHook`。
- 系统对照为 `reference/SYSTEMUI_BASELINE.json` 指定的 OS4.0.2.0.XPCCNXM；使用 aapt2 读取正式基线 APK 资源，未采用其他版本的反汇编或资源 ID。

### 布局细节

- ID 0/1：封面与父容器左、上、下边距各 9 dp；文本距封面右侧 12 dp。ID 0 右侧三键间距 0 dp、右边距 14 dp。默认卡片圆角 22 dp、封面圆角 14 dp。
- ID 1 名称虽为“歌词封面”，布局代码仍引用 `header_title`、`header_artist`。未发现其新增歌词解析、同步或专用歌词视图，文本内容取决于系统/媒体应用。
- ID 2：封面左/上/下边距 11 dp，文本与封面相距 14 dp；歌名位于歌手下方 2 dp。卡片圆角 30 dp，布局后封面圆角 22 dp。`patchSwap` 中投放可见性有单独写入，不宜只按 hideSeamless 配置推断最终行为。
- ID 4：封面左/上边距 14 dp、圆角 12 dp；三键各 34 dp，action0/4 使用约 37.4 dp 后取整的边长。action4 位于封面下方，action0 在右上；投放位于右下。action0 还有布局后向上 4 dp 的平移。扩展动作槽的图标/语义由媒体应用提供，不能固定解释为收藏或循环。
- `postApply` 还调整文本字号、字体留白、按钮 padding、进度及时间视图的布局留白。仅转写 ConstraintSet 不保证像素级一致。
- 官方默认基线的普通媒体高度为 185 dp、封面 52.5 dp、动作按钮 60 × 50 dp；这是基线资源值，不应套用为其他 ROM 或超级岛的固定高度。本模块现有“系统默认”预设显式取 168 dp，两者不能混称。

## 超级岛边界

`MediaSessionHook.isMedia(View)` 明确拒绝：

1. 类名包含 `Island` 的视图；
2. 子树内含 `media_bg_view` 的视图。

只有包含 `album_art` 和 `action1` 的普通 ConstraintLayout 才继续处理。因此，此样本的四个自定义样式不能认定为已支持超级岛。向本模块超级岛移植属于新增适配。

## 本模块接入方案

当前代码已有 `MediaLayoutPresets` 的 system/compact/standard/custom，普通与岛内布局分别存储，且有 `MediaConstraintCustomizer`、`MediaIslandHostHooks` 的高度同步路径。

- 按用户后续确认，使用参考 ID 0 替换原紧凑预设，默认高度 80 dp；将 ID 2 新增为“大封面”，标识 `large_cover`，默认高度 148 dp。保留原标准与自定义预设。官方默认沿用现有系统选项。
- 将四套排版转成独立、可验证的约束定义，普通卡与岛内卡分别适配。岛内背景使用 `media_bg_view`，普通卡使用 `media_bg`；不能仅替换背景 ID 就认定兼容。
- 现有 XML 覆盖采用增量修改，需清除与新排版冲突的旧约束；尤其核对 start/end 与 left/right 约束、`actions` 容器、岛内 action4 的系统绑定，避免照搬普通卡结构。
- 高度通过现有媒体岛根视图与插件宿主路径同步，禁止全局覆写 `expanded_island_height_dp`，避免影响其他超级岛卡片。
- 更新预设白名单、持久化/导入导出、运行时选择、编辑器模板及预览；保留关闭恢复、兼容模式和多模块边界。
- 验证预设双向切换、关闭恢复、普通/岛内两种表面、长标题、缺少扩展动作、投放、字体缩放、AOD、RTL及横竖屏。

- 无关设置变化跳过媒体根高度刷新和约束回放；同一目标的排队刷新合并，执行时读取最新设置。既有待刷新约束记录改用 Context 弱引用。

## 性能审查

样本使用通用 `ConstraintSet.applyTo`、`View.onFinishInflate` 以及三个 Resources 尺寸方法的 Hook；在候选布局检查中进行资源/子视图查找。绑定后注册布局监听，立即及延迟 300 ms 应用，并在布局尺寸不符合时重新 post。计数在符合预期后会移除，因此不能将其解读为整个生命周期最多重试九次。

后续移植仅复用排版参数，不复制其通用 Hook 和布局重试机制。优先使用本模块已有的媒体目标过滤与生命周期；稳定资源 ID、反射访问方案及解析后约束应缓存，设置变化只更新相关目标并合并排队任务；不得强引用 View/Context，也不得新增模糊、截图层、轮询或 IPC。

以上为静态代码审查及接入设计。本次仅运行本地编译和 Robolectric 回归，没有运行真机 Android 布局、微基准、Perfetto、FrameTimeline、CPU/分配采样或耗电测量，不能声称流畅度或功耗已有改善。


## 2026-11-05 锁屏越界修复

用户真机截图出现背景与封面/进度错位，以及 Spotify 收藏和随机播放按钮露出。

确认的两条路径：

1. 原模板封面上下锚定 `parent`，而背景已有独立固定高度。真实 ConstraintLayout 2.2.1 测量中，将外层保持为 240 dp 时，紧凑封面位于 y=89..151、背景 y=0..80；大封面位于 y=57..183、背景 y=0..148，均越界。修复后内容锚定媒体背景，普通及岛内引用分别映射到 `media_bg` / `media_bg_view`。隐藏侧槽还清除原约束并归零尺寸，避免晚到的可见性变更保留旧几何。
2. 模块的 `SpotifyMediaCardBinding.bind` 原先强制显示 action0/4，覆盖了紧凑和大封面约束中的 GONE。现在绑定查询同一份缓存约束计划，遵守预设及用户 XML 的可见性。元数据绑定、投放与 AOD 状态回调也重申显式 GONE 策略，不强制将系统隐藏的控件显示出来。

显式可见性覆盖还会恢复 ConstraintSet 的 `mVisibilityMode=0`。运行时处理仅位于媒体目标 apply/绑定及已有 AOD/投放回调；缓存类字段和约束计划，不增加绘制、触摸、逐帧、全局 View 可见性 Hook、布局重试、轮询或 IPC。

新增的真实 AndroidX ConstraintLayout 依赖只进入 debug，以提供本地求解测试所需的资源类，不进入 release APK。之前仅验证字段赋值的模拟测试不足以发现父容器测量与背景高度不一致的问题；本次补充真实求解、晚到的 Spotify 绑定、用户 XML 覆盖和 AOD 可见性回归。该验证不替代真机 ROM、动画与多模块共存验证，也不提供帧率或耗电改善结论。


## 2026-11-05 已确认的 136 dp 五键版本

按用户确认替换“大封面”的默认排版：卡片高 136 dp，封面 104 dp；保留歌名、歌手、30 dp 投放入口，五个原生动作按 action0/1/2/3/4 同排，播放键最大。进度容器为 14 dp，移除文字和进度视图的竖向留白。根据实际字体行高预算动作行高度，支持 1.3 倍字体；不在逐帧或绘制回调中计算布局。

封面圆角由通知圆角减去较小的水平/竖向内缩量计算，并限制在 0..封面半边长。默认通知圆角 28 dp、水平内缩 12 dp 时，封面圆角为 16 dp；关闭通知圆角覆盖时读取系统 notification_item_bg_radius。通知圆角变化加入相关媒体设置刷新判断。

新增 hook 仅覆盖已有 SystemUI 媒体控制器的布局完成与绑定方法，确保系统重新应用 TextAppearance 后保留排版。无新增进程、桥接、模糊、截图层或定时任务。验证使用 Robolectric 原生图形模式获得实际字体度量，覆盖普通/岛内、320/396/400/440 dp、字体缩放、圆角实时变化与恢复。构建目录保存原生控件的离屏排布图；这些图不包含 ROM 的玻璃材质，不能替代真机外观和动画验证。没有 FPS、卡顿率或功耗对照测量。

## 2026-11-05 进度轨道裁切与动作图标修复

用户反馈 136 dp 版本只留下动作区下方的一条淡线。正式基线的 `HyperProgressSeekBar` 不是普通 SeekBar：构造时在 `initShaderConfig()` 中将 `uTrackPosition.y` 固定为 19 dp，并写入 RuntimeShader；`onSizeChanged` 只更新画布/分辨率，`onLayout` 更新宽度和 RTL，不重算这个 y。将控件压到 14 dp 后轨道中心已在画布外，不能只靠去除 padding 修复。

默认进度容器改为 18 dp，在现有媒体 apply/绑定边界同步缓存 y 和 shader uniform 到控件高度的一半，同时按原生当前 maxHeight 计算竖向 padding。保留原生 6..12 dp 轨道高度、颜色、拖动和动画路径；离开大封面恢复原缓存 y 与原 padding。反射字段按 ClassValue 缓存，位置快照以弱 View 键保存标量；只有位置变化时写 uniform 和 invalidate，不新增绘制/触摸/逐帧 Hook、监听重试、IPC 或额外 GPU 层。

五键宽度调整为 32/36/40/36/32 dp；按文字度量预算可用高度，减小两侧按钮与中央按钮的高度差。大封面按钮清零 padding 并使用 FIT_CENTER，使原生小尺寸图标可以放大；紧凑仍使用 CENTER_INSIDE，离开预设恢复原属性。设置预览同步较大的次要图标和 6 dp 轨道。

回归补充带构造缓存坐标的测试 SeekBar 与实际 RuntimeShader。通过 RenderNode/硬件 Canvas 离屏绘制验证修改前中心像素透明、修改后轨道可见且活动/未活动段有差异，同时核对拖动高度、重复绑定和原值恢复。普通 Bitmap 软件 Canvas 不支持 RuntimeShader，因此这些测试改用硬件绘制；测试 shader 是用于验证缓存坐标契约的简化 shader，不是 ROM 全套玻璃材质。真实 ConstraintLayout 测试核对动作不与歌手、进度重叠，覆盖普通/岛内与字体缩放。40 项相关回归通过。以上属于本地回归和静态性能审查，仍需真机确认 ROM 着色器完整外观、拖动动画和多模块共存；未进行帧率或功耗对照测量。


## 2026-11-06 独立表面、AOD 与光晕空间

媒体通知与超级岛分别选择预设，并分别保存每个预设的高度；原有两套 XML 继续独立。旧配置没有新选择器时保留旧共用选择；第一次编辑一侧会固定另一侧的原选择/高度，后续互不跟随。设置、本地存储、备份和运行时 Bundle 均包含新字段。普通媒体选择系统、超级岛选择标准时，标准排版不再依赖普通媒体的 mediaEnabled 开关。刷新快照按表面比较，修改通知预设/高度/XML 不重放独立超级岛。

通知“大封面”改为 action1/2/3 三键，统一 36 dp 按钮区域，隐藏 action0/4；图标素材本身的透明留白仍可能造成视觉重量不同。默认通知高度按用户最新反馈改为 140 dp，时长暂留在进度条下方；封面仍为 104 dp。超级岛“大封面”保留五键模板及 136 dp 默认值，用户可以改选原五键标准布局。布局版本 3 将未编辑的旧通知默认高度迁到 140 dp，旧岛内高度保留，自定义 XML/非默认高度不覆盖。

用户进一步发现进度条上下光晕裁切。正式基线 `music_player_tracker.frag` 的发光头纹理按 38 dp 比例采样；18 dp 画布虽然显示轨道，但会裁掉光晕。恢复原生 38 dp 画布与居中坐标，利用其上下透明留白安排相邻控件；动作行底部锚定时间行，避免按整块透明画布挤压按钮。保持 140/136 dp 卡片高度，保留原生 shader、纹理、动画和拖动，不增加绘制层或关闭光效。绘制像素区域比上一版 18 dp 增加，恢复到系统原始画布规格；这属于完整光效所需空间，未测量 GPU 时间或功耗变化。

AOD 原生回调只缩短背景并隐藏进度/时间，不能适配展开态的 104 dp 封面。现在仅在实际 AOD 状态切换时，同步重载已观察到的普通媒体与内层封面 ConstraintSet；不重放岛内表面。进入 AOD 时跳过展开预设，恢复系统小封面及文字属性，再把封面与主副标题组垂直居中；退出时重载当前独立预设。重载保留原有目标记录，元数据/Spotify 的晚到绑定仍遵守隐藏策略。弱引用记录不保留 View/Context；方法访问按 ClassValue 缓存，不新增帧回调、定时器或布局重试。

验证包括真实 ConstraintLayout 的重复 AOD 进入/退出、外层与内层图片恢复、主副标题组居中、通知三键与岛内五键、字体缩放、预设/高度的存储与备份迁移、普通/岛内刷新隔离，以及带柔和光晕的 RuntimeShader 硬件离屏像素边界。45 项相关回归通过。测试 shader 是契约模拟，真机 ROM 的完整材质、AOD 过渡动画、不同音乐应用及多模块共存仍待设备确认。本轮只有本地回归、编译和静态性能审查，未做帧率、卡顿或功耗测量。
