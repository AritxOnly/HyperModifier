## 已修正的结构性开销

| 路径 | 优化前 | 优化后 |
| --- | --- | --- |
| 同一 View 连续设置半径 | 每次创建状态对象并写 WeakHashMap | 首次创建，后续查找并原地更新原始半径 |
| 启用时半径计算 | 创建 int[2]，再创建 Hook 参数数组 | 标量计算，仅确需替换时创建 Hook 参数数组 |
| 系统半径已等于配置 | 仍替换参数 | 直接 proceed，复用原参数 |
| 无关设置变化 | 遍历所有目标并给每个 View 投递任务 | 对有效启用状态/半径去重，无遍历或投递 |
| 连续相关设置变化 | 每次给每个目标追加回放 | 每个 View 至多一个尚未执行的任务，执行时读最新配置 |
| 回放值已生效 | 再次反射调用 setter | 根据已应用半径跳过重复 setter |
| 尚未完成设置加载 | 半径回调调用 ActivityThread 反射查找 Application | 使用当前 View 的 Context 调度异步加载 |
| 新增作用域进程 | PackageLoaded 安装 ContextWrapper / Application 通用设置 Hook，并接入桥接 | 只读设置安全门及 Glass 半径，原有业务功能仍由 PackageReady 启动 |

保持原值追踪，即使 Glass 开关关闭，也保留每个已观测 View 最近的系统半径，确保以后开启能更新现有界面。
因此关闭 Glass 时仍有一次弱表查找和字段写入；这是实时切换的成本，不宣称关闭路径零开销。
兼容停用或模块停用的拦截路径直接透传，不访问弱表。缓存值不持有 View、Context 或 Activity。
兼容停用暂停回放；关闭普通 Glass 开关恢复系统最新半径；系统自身动画调用从不被整个跳过。

## 2026-10-14 超级岛内层不透明度

展开背景的 `EXPANDED_GLASS_TOKEN` 在当前插件里使用 RGB 0.06/0.06/0.06、alpha 0.6。
`BionicsToken.toBionicsParams` 的槽位 14 对应内层 alpha，槽位 18 才是整体 alpha。
新增 0–100% 设置，默认 30%；仅修改槽位 14，保留文字、图标和其他 shader 参数。
沿用展开背景更新 Hook，不新增通用或逐帧 Hook。关闭模块/Glass 时回放原始配方，
内容关闭或转为非 Glass 时移除弱目标，并使旧排队任务失效；收起小岛不登记为目标。

缓存反射访问和原始配方；不透明度改变时至多克隆一次配方，普通半径/无关设置变化不遍历着色目标。
相关设置任务按目标合并，滑块在松手时提交。默认非系统值会在系统材质更新事件后多调用一次
现有原生 Glass setter；没有增加模糊采样层、截图、IPC、文件访问或常驻定时器。
这是代码和反编译路径检查，尚无该新增路径的真机帧耗时/耗电前后对照。

本轮 35 项相关单元测试通过，覆盖 shader 非 alpha 参数/原配方不变、0/100% 边界、
原半径恢复、收起状态和材质预设不会覆盖不透明度设置。签名 Release 构建及 APK v2 验证通过。

## 2026-10-14 下拉小窗、通知中心与设置归属修正

之前的透明度补设依赖展开采样 root，因此下拉小窗切换到 fakeExpandedView 时未覆盖；
只补设一次也不能保持后续系统材质写入。现将着色登记与采样 root 分离，
并在 `onTrackingFakeViewStart` 这个手势生命周期事件中更新既有替身背景材质。

apply 前登记、clear 前移除。普通通知和收起小岛不因此登记。

复用已安装的 View.setMiGlass Hook，只对弱表里登记的 View 修改槽位 14。
未登记路径首先读取 hasTargets，后续弱表查找即可退出；不用新增调用栈或树遍历。
动画连续写入复用每目标两份 float 缓冲，保留最新系统配方，包括整体 alpha、颜色等动画参数；
每次修改仍需 libxposed 的替换参数 Object[]，不声称零分配。
原生材质更新不再在事后重复调用一次 setter。相关设置回放合并，材质清除使旧任务失效；
精确着色会移除旧通用卡片回放，防止设置刷新重新覆盖透明度。

设置移动到“超级岛与媒体组件 / 超级岛背景”，新增独立开关，旧版本沿用此前全局开关
作为未保存新开关键时的默认值，保留既有不透明度数值。新开关与数值均参与保存、远程同步及备份。

本轮 36 项相关测试通过。新增连续材质写入回归验证：同一缓冲复用、透明度保持、

## 2026-10-14 功能确认后的代码性能复查

用户确认功能可用，并选择本次只做代码检查。ADB 未连接；未采集 Perfetto、FrameTimeline、
CPU/分配采样、启动耗时或耗电前后对照。以下结论来自源码路径审查和回归测试，
不能推导 FPS、卡顿率或耗电改善幅度。

| 范围 | 发现 | 本轮处理 |
| --- | --- | --- |
| 连续原生 Glass 写入 | 每次精确着色都移除通用卡片弱表，产生额外共享锁操作 | 仅首次接管/有效配置切换时移除，设置回放前移除；连续相同配置不重复清理 |
| 锁竞争 | 42 项有限性校验、原配方复制和着色复制都在目标弱表锁内 | 锁仅保护查找/生命周期移除；配方处理在锁外，沿用目标 UI 线程及 View.post 回放 |
| 主线程首次加载 | 通用材质入口 ensureLoaded 会反射查找 ActivityThread/Application | 与全局半径路径一致，使用当前 View.Context 调度异步加载 |
| 无关设置变化 | 通用卡片 refresh 在任何设置变化后都会全量快照/排队/重放 | 对自身有效开关和配方值去重；关闭时忽略配方编辑；启停/有效配方变化仍刷新 |
| SystemUI 启动 | PackageLoaded / PackageReady 重复查找焦点通知类和方法 | 全部安装成功后快速退出；部分失败仍保留重试及逐方法防重复 |

连续材质写入仍需至多两次弱表查找、42 项校验、原值跟踪及最多两次 42-float 复制。
每目标复用两份 42-float 数组，数组有效载荷共 336 字节，另外还有 JVM 对象头及弱表/状态对象。
确需替换参数时仍会创建 libxposed Object[]；没有每次新建 float[]，不宣称零分配。
View / Context 仅出现在弱键、WeakReference 或有界 View.post 生命周期任务中，缓存值不强持有它们。
设置队列每目标合并，旧状态身份不匹配时取消回放。

IPC/磁盘/耗电：材质热路径没有新增同步 IPC、读写、轮询或常驻定时任务。
GPU：沿用系统 shader、采样缓冲与半径入口，没有增加采样层或截图层；透明度改动仍可改变
画面混合结果。更大 Glass 半径的 GPU 成本无法由源码判定，本次没有测量。

剩余已知热点：未走精确超级岛覆盖的通用卡片分类仍有调用栈采集/祖先检查，
普通卡片配方调节仍会分配新数组；它们是既有路径，本次没有改变其路由和实时启停边界。
关闭超级岛自定义时继续记录最新系统配方，以支持实时启用/原值恢复；保留了这部分必要开销。
性能记录替代上方历史阶段描述，以本节及当前源码为准。

验证结果：39 项 Glass 相关单元测试通过（0 失败/错误），其中新增 120 次连续写入
保持缓冲复用且不重复清理通用卡片、独立启停/最新原值恢复、相同配方重新解析
和关闭时编辑配方不触发刷新等回归。Release 构建、APK v2 签名及 git diff --check 通过。
