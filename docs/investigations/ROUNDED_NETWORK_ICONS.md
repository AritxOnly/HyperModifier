# 圆润信号和 WLAN 图标

2026-10-22。入口：状态栏 → 状态栏信号 → **圆润信号和 WLAN 图标**，默认关闭。独立键 `rounded_network_icons` 已接入模型、预设复位、SharedPreferences、设置 Bundle/备份 schema、运行时和 SystemUI 修改状态标识。

## 静态分析与边界

分析本地 `reference/systemui-4.0.4.0/` 对应 APK。该样本与既有 4.0.2.0 默认 SystemUI 基线哈希相同，沿用现有基线边界，没有混入其他版本资源 ID。

`status_bar_mobile_signal_group_inner.xml` / `status_bar_wifi_group_inner.xml` 的 `mobile_signal` / `wifi_signal` 均为 `AlphaOptimizedImageView`。MiuiMobileIconBinder 与 MiuiWifiViewBinder 通过 `ImageView.setImageResource` 赋资源，深浅色/tint 变化也会经 `MiuiStatusBarIconViewHelper.transformResId` 重绑相应资源。Wi-Fi binder 使用 ImageView.setImageTintList，所以不能把原 VectorDrawable 的内部 tint filter 当成显式 ColorFilter 冻结在新图形上。

原资源是 20 × 20 viewport 的填充 VectorDrawable，没有可直接调整的圆角半径。移动信号为四个圆角柱的不同亮/暗层组合；WLAN 包括三档弧线/底部三角形，版本数字、上下行箭头和 5G/VoLTE 等由其他 View 表示。

覆盖资源名：

- `stat_sys_signal_0..4`，包括 no_voice、darkmode 和 tint 变体。
- `stat_sys_wifi_signal_0..3`，包括 darkmode / tint。
- unavailable 与 slave_wifi 变体内仍保持标准几何的完整弧线。

资源名严格匹配，且仅识别已知信号柱和弧线的 pathData 前缀。不处理 WLAN 底部三角形、版本数字、无网络警告、双 WLAN 标记、上下行箭头、5G/VoLTE、无服务/飞行模式/卫星等特殊资源。无网络和双 WLAN 标记旁的特殊窄端弧线保持原样：原生测试发现统一处理会缩短这些端部。未知资源、含 group/clip-path/stroke/trimPath/root tint 的主题、非 20 × 20 viewport 或解析不支持时保留原图。

## 圆角与绘制

`RoundedNetworkDrawable` 读取支持的系统矢量资源，保留每条 path 的填充颜色/颜色状态列表、透明度和 fillType。路径只在首次使用对应资源时计算：先用 round join/cap 的边界描边从原图侵蚀出内部，再恢复圆润边界，最后与原图相交。移动信号与 WLAN 完整弧线均使用 1.1 viewport 单位。圆角阶段沿用原始路径内的结果，不再逐路径校准外框。按用户后续要求，WLAN 整个图形以 (10,10) 为中心统一等比放大 1%；图标 View 的尺寸、位置和间距不变。无数字实心电池已恢复为宽 98% / 高 94%，不再随圆润开关改变尺寸。

绘制时只使用缓存的填充 Path 与 Paint，不进行资源解析、反射、Path 布尔运算、图片采样、模糊或对象创建。Drawable 支持 ImageView 的 tint list、BlendMode / PorterDuff mode、颜色状态、alpha 和显式 ColorFilter；未点亮的信号层仍保留其透明度。根 alpha 与 Drawable alpha 只应用一次。

## Hook、恢复与兼容

使用一个 ImageView.setImageResource Hook，因为两个目标类继承该方法，并未各自重写。先检查精确 View 类和两个缓存 ID，非目标立即返回；资源处理仅在 UI 线程、指定两种图标上发生。关闭时仍记录这两个目标的最新资源 ID，以便实时开启；不扫描 View 树或反射 Drawable 私有路径。另有两个网络根 View 的专用 onConfigurationChanged Hook，配置变化时只重建本模块仍持有的圆润图标，重新读取密度/主题资源。

原图和替换图均使用弱引用追踪，弱键表的值不强持有 Drawable 回调中的 View/Context。关闭功能、停用模块或进入兼容模式时，仅当当前 Drawable 仍是本模块替换对象才按最新系统资源 ID 恢复，包含暂时离屏的 View；未知 Drawable 赋值不被覆盖。资源定义按弱 Resources、配置及主题代次缓存，最多 128 项，也缓存不支持结果，避免重复解析失败。

其他模块若在同一目标上强制替换 Drawable，最终效果仍受 Hook 顺序影响；本实现不劫持其他 View 的 tint/alpha/visibility，不扩大 LSPosed 作用域。
